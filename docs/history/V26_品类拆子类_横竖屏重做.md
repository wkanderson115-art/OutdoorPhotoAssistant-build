# V26 · 品类拆子类 + 拍摄页横竖屏重做

这轮两件事：**把「汽车与机车」里混着的两种题材拆开**（棚拍商品图 vs 街头纪实），
以及**把拍摄页横屏做成系统相机的样子**——之前横屏取景框只有 26.5%，基本没法用。

---

## 第一步：品类拆子类（预设粒度）

问题：`汽车与机车` 这一类的 4 个预设被统一按 `product` 口径（纹理 0.60–1.45）判，
但其中「机车写真」「汽车夜景」是**街头纪实**，交付标准是「像现场」（scene 0.60–1.20）。
上一轮真图验证里就暴露过：车队照片纹理 1.233，product 口径合法、scene 口径超限。

改法：不动 20 个大类（用户看到的分类不变），在**预设粒度**加一张白名单：

```swift
// RetouchPresetCatalog
static let sceneModePresetIDs: Set<String> = ["p16", "p27", "p58", "p59"]
// p16 街头穿搭（时尚与穿搭）：随身街拍
// p27 城市纪实（风景摄影）：街景纪实
// p58 机车写真（汽车与机车）：街头环境里拍车
// p59 汽车夜景（汽车与机车）：夜间街景，暗部压缩本来就掉纹理
```

`shootingMode` 增加 `presetID` 参数，商品/建筑/汽车/静物这四类里命中白名单就走 `.scene`：

```swift
case "商品摄影", "建筑与室内", "汽车与机车", "静物与艺术":
    return RetouchPresetCatalog.sceneModePresetIDs.contains(presetID) ? .scene : .product
```

优先级仍是：截图 → document > 文档与翻拍 → document > 商品类 → product/scene（按预设）> 人脸 ? portrait : scene。

## 第二步：拍摄页横屏重做 + 竖屏控制区压缩

### 先说量化证据（`tools/retouch_lab/layout_probe.py` 可复跑）

| 机型 | 竖屏现状(5 行) | 竖屏新版(2 行) | 横屏现状(右侧栏) | 横屏新版(浮层) |
|---|---|---|---|---|
| iPhone 15 | 235×313 · **28.4%** | 352×470 · **64.0%** | 176×132 · **26.5%** | 416×312 · **47.5%** |
| iPhone 15 Pro Max | 295×393 · 36.5% | 412×550 · 71.4% | 225×169 · 31.0% | 465×349 · 48.8% |
| iPhone SE3 | 151×201 · **14.8%** | 268×358 · 46.9% | 180×135 · 32.0% | 420×315 · 52.9% |
| iPhone 13 mini | 212×282 · 25.3% | 329×439 · 61.4% | 152×114 · 22.9% | 392×294 · 45.7% |

横屏 47.5% 已经是数学上限：4:3 图放在 734×372 的区域里只能这么大，
**左右留黑边正是系统相机的横拍形态**（不是 bug）。

### 核心改动：布局数学先抽成纯函数

`CaptureLayout.plan(available:landscape:aspect:topBar:bottomBar:)` 返回
`preview / previewArea / overflow / fillRatio`：给多少空间、扣掉什么、取景框多大、有没有溢出，
全部可单测。`tests/layout/main.swift` 新增 11 条断言（含「旧横屏必须 <30%」的回归保护），
CI 的 `typecheck.sh` 会编译并运行它。

### 竖屏：控制区 5 行 → 2 行
- 第 1 行 `filterRow`：横向滚动的滤镜图标胶囊（38×38）+ 右侧「更多」；
- 第 2 行 `zoomAndIntentRow`：变焦胶囊 + 当前倍率（点开变焦 sheet）+ 意图 Menu 胶囊 + 效果前预览长按胶囊；
- `selectedRow`（主体已选 + 曝光滑杆）改成**取景框内浮层**，只在选中主体时出现，不占布局；
- 快门条仍是 `safeAreaInset`（竖屏），不遮任何一行；
- reserve 由实测高度回灌（`≈129`），初值与兜底常量从 288 改成 130（首帧不再跳）。
- 大字号兜底：reserve 涨到 180 时 iPhone 15 仍有 50.8%、overflow=0。

### 横屏：系统相机形态
- **删掉右侧 250pt 控制栏与整个 ScrollView**；
- 取景框 `plan(landscape: true, bottomBar: 0)` 居中，左右黑边；
- 控件全部 `.overlay`（不占布局）：

| 元素 | 位置 |
|---|---|
| 顶栏 | 顶部 52pt |
| 滤镜入口 / 意图 | 左上（leading 16 · top 60） |
| 相册缩略图 | 左下（24 / 37） |
| 变焦胶囊 + 当前倍率 | 右下快门上方（28 / 108） |
| 快门 72pt | 右下（28 / 24） |
| 自动拍摄 暂停/恢复 | 快门左侧（116 / 37） |
| 导演单行 | 取景框底部居中（8） |
| 主体浮层 | 取景框底部（36，压在导演条上方） |

- `safeAreaInset` 条件化：`if !uiIsLandscape { shutterBar }` —— 横屏不再被快门条吃掉 100pt。

### 顺带修「假横拍」隐患
`outputAspect` 原来跟着 UI 方向走。旋转瞬间按快门时，UI 还是竖的、成片已经是横的，
就会把横图按 0.75 竖裁 —— 看起来像「竖拍」。现在：

```swift
let photoIsLandscape = shot.image.size.width > shot.image.size.height
if photoIsLandscape != uiIsLandscape { options.outputAspect = 0 }   // 不裁，保留全画幅
```

宁可留全画幅，也不裁错方向。

## 真机待确认（静态检查替代不了）

1. 横竖切换有**一帧滞后**：`uiIsLandscape` 由布局回写，切过去那一帧快门条还在，会看到一次预览跳动（自愈）。
2. 横屏快门距底 24 是相对内容区（底部安全区 21 已扣），视觉离屏幕下缘约 45pt——要更贴边可挂 `ignoresSafeArea` 层。
3. 横屏浮层会压在画面右下角（系统相机也这样），确认可接受。
4. 竖屏第 2 行「横向滚动滤镜」与「效果前预览长按」相邻，快速横滑可能误触长按。
5. AX5 超大字号：SE3 竖屏会掉到 ~34.5%（取景框有 140pt 下限），要不要把控制区改可滚动由你定。
6. 成片方向：竖屏应出 3:4、横屏应出 4:3，需要真机各拍一张核对。
