# 18d 修复说明（源码级，待 Xcode 真机验证）

## 精修台

定位到 `RetouchBatchRunner.performPrepare`：原代码在未找到人脸/肤色时直接把照片设为失败，并要求 `ShootAnchor` 非空才进入 `process` / `processOne`。因此城市夜景等无人脸照片在进入调色流水线之前被阻断。

已改为：无人脸照片仍处于待处理状态；若整批无人脸，则不生成肤色锚点，调用 `RetouchPipeline.process(... anchor: nil)`，使用现有通用色调与调色处理。有人脸照片仍沿用肤色分析与批次锚点。单张重试同样适用。

注意：截图未展示具体错误日志，因此此项是源码中发现的明确阻断条件，不保证是此次失败的唯一原因。如果修复后仍失败，应查看单张照片的 errorMessage 和设备日志。

## 手动与自动变焦

`CaptureView` 新增明确的自动/手动模式切换，手动模式展示连续滑杆及数值输入；数值按 0.01× 量化。手动输入和捏合均阻止自动导演抢回倍率；可以恢复自动。`CameraService` 的用户变焦上限设为 min(100×, 设备当前支持的最大倍率)。

100× 是软件请求上限，不是对设备物理能力的承诺。超出设备支持的倍率不强行伪造，也不意味着 0.01× 的变化对应可见光学分辨率变化。

Linux Swift 前端语法解析已通过（仅改动的三个 Swift 文件）。未进行 iOS SDK 类型检查、Xcode 编译、iPhone 真机测试、夜景精修运行测试。建议用同一张夜景复测，检查 `失败` 是否变成 `已处理`，然后测试手动倍率、自动恢复、前后摄切换、0.01 倍输入和最大倍率边界。
