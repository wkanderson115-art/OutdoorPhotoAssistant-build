## ④ 融合重做：`SafeFusion`（78 → 592 行）

### 旧实现为什么等于不存在

把两图缩到 **128×128** 逐像素比 RGB 差，硬门禁要求「差异 >12 的像素占比 < 8%」
且「差异 >65 的像素为 0」，否则直接抛错。AI 只要动了光影或肤色，`changed` 立刻超 8%
——这个功能从来没被触发过。而且 128×128 根本分辨不出「结构被重绘」。

### 新实现：遮罩引导 + 分块投票

```
512 长边代理 → 逐像素 Lab ΔE00 → 16×16 = 256 块投票 → 256 块权重平面
→ 双线性放大到全分辨率 → 高斯羽化（长边/300）→ CIBlendWithMask
```

逐块投票（顺序不可颠倒）：

| 判定 | 条件 | 结果 |
|---|---|---|
| 结构被重绘 | `structure < 0.90` | 拒绝该块 |
| 过度编辑 | `meanΔE > 14` | 拒绝该块 |
| 无需改动 | `meanΔE < 1.2` | 权重 0（不计采纳率） |
| 采纳 | 其余 | `w = clamp((structure-0.90)/0.08) × clamp((14-meanΔE)/6)` |

乘性约束：
- 传了主体遮罩且该块主体占比 <0.5 → `w ×= 0.35`（背景不许被 AI 顺手改）
- `allowsGenerative == false`（纪实/商品/建筑/文档类）→ `w ×= 0.5`

全局兜底（任一命中就 `applied:false`，保留本地方案）：
采纳面积 <5%、采纳区平均 ΔE >10、结构拒绝 ≥3 块。

**预期行为**（Python 完整 CIEDE2000 复现投票逻辑验算过）：

| 场景 | 结果 |
|---|---|
| 只改脸部肤色/光影 | 采纳 13%（脸部以外算 noChange）→ **applied** |
| 典型商业精修（全局轻调 + 肤色 + 背景微提亮） | 采纳 55–100%，ΔE 2.1，结构 1.00 → **applied** |
| 全局重调色（结构保留） | 采纳 100%，ΔE 8.7 → applied（权重 0.89） |
| AI 换背景/重绘人物 | 结构拒绝 176 块 → **applied:false**，理由写清「检测到 176 块结构被重绘（人物/边缘），已保留本地方案」 |
| 磨皮过头（纹理被抹平） | 结构拒绝 38 块 → 回退，保住毛孔 |

**兼容**：`conservativeMask(local:ai:)` / `blend(local:ai:mask:)` 签名不变；
不采纳时 `conservativeMask` 返回全黑遮罩（= 全保留本地），不抛错；
`Failure.renderFailed` 保留（既有调用点还在引用）。

**性能**：决策 ≤0.25s（代理 40–70ms + ΔE00 70–140ms + 遮罩 10–20ms），
全分辨率分块混合 150–350ms → 12MP 约 0.30–0.45s，24MP 约 0.55–0.75s。

**调用点改造**（`CommercialRetouchView.runAI` 的 dual 分支）：
现在会先用 `RetouchBackgroundEngine.subjectMask` 取一张主体遮罩传进去（背景块权重压到 0.35），
并且对「商品摄影 / 建筑与室内 / 文档与翻拍」三类强制关掉生成式额度。
状态栏会直接显示决策结果：
`融合采用 62%（158/256 块）· 平均 ΔE 4.2 · 结构 0.97；…`
未采纳时显示最狠的那条理由，而不是旧版的「自动融合拒绝：渲染失败」。

## ⑥ 批处理接 AI 建议

### 逻辑抽成共享模块

单张精修页里那套成熟规则（11 条判定 → 指标/现象/动作/参数 + Seedream 提示词）
原来写在视图里，批处理用不到。现在抽到
`Core/CommercialRetouch/AIEditAdvisor.swift`（318 行，纯 Foundation）：

```swift
struct AIEditSuggestion: Identifiable, Equatable { metric / finding / action / parameter }
struct AIEditAdvice: Equatable { items / prompt / recommendedPresetID / recommendedStrength / headline / failureCount }
enum AIEditAdvisor {
    static func makeAdvice(report:look:presetID:strength:spotsFound:spotsRemaining:) -> AIEditAdvice
    static func noteFallback(_:keyword:) -> String?
    static func brief(_:) -> String           // 一行摘要
    static func batchSummary(_:photoCount:) -> String
}
```

阈值口径与视图侧**逐字一致**（肤色 ΔE 3.00/1.50、裁切 0.0100/0.0020、纹理 0.50、
接缝 0.30、SSIM 0.85、强度步进 0.05 / 下限 0.70 / 上限 1.30）——
单张与批量共用同一份，不会再出现「两处阈值漂移」。

### 批处理链路

- `RetouchBatchRunner.performOne`：每张 `pipeline.process` 成功、写回 report 之后，
  立刻算建议并写 `photo.advice`（主线程，与 resultURL/report 同一批写回）；
- `BatchPhoto` 新增 `@Published var advice: AIEditAdvice?` 与 `needsAI`（`failureCount > 0`）；
- 新增 `@MainActor func refreshAdvices(for job:)`：对已处理/已通过的照片**补算建议**，
  不重新渲染、不写盘（纯计算，毫秒级）；
- 新增 `needsAICount`：视图直接读，`@Published job` 自动刷新。

### UI

1. **批次汇总卡**（`progressCard` 之后）：一句话汇总
   `12 张中 5 张本地未合规（肤色 ΔE 3 张、整体裁切 2 张）；建议统一用「商业自然」+ 强度 0.85 跑一轮 AI`
   + 按钮「为已处理照片生成建议」+ `N 张建议再做一轮 AI`；全合规时显示「可按当前设置直接交付」。
2. **逐张审核弹窗**（质检面板下方）：建议卡逐条展示 指标/现象/动作/参数 + 完整提示词，
   两个按钮「复制提示词」「打开 AI 修图页」（`NavigationLink` 到单张双引擎页）。
