# V17 影楼商业版 · 交付说明

## 0. 一句话

在 V16 精修引擎之上补齐了「可营业」的四件事：**整批色彩一致（套系锚点）、液化、换底与证件照、交付包与选片页**，并给了一套 20 张/天的审核流程。机器负责初修与质检，人只做三件事：液化微调、点补瑕疵、过/不过。

## 2. 20 张/天的实际跑法

1. **导入**：工作台选片（≤60 张），自动建立批次。
2. **分析**（约 1–3 s/张，看机型）：逐帧分析皮肤、曝光、白平衡，算出**一个**套系锚点。
3. **精修**：逐张串行出片，每张同时给出质检报告；失败的会标红并写明原因。
4. **审核**：点开缩略图 → 看质检面板（纹理保留/肤色 ΔE/接缝/SSIM/裁切）→ 需要时拖液化、选背景、勾证件照 → **重新精修** → 通过或淘汰。
5. **套用**：一套片风格统一后，用「应用到本批」把参数推给所有照片，再逐张只调液化。
6. **交付**：填交付设置（网页长边/质量、全尺寸格式、色彩空间、水印、文件名前缀）→ 导出 → 得到 `<前缀>_交付包.zip`（内含 `web/`、`full/`、`idphoto/`、`proofing/index.html`、`manifest.json/csv`）→ ShareLink 直接发给客户或拷到硬盘。

20 张的节奏：机器 1–3 分钟，人审 2–4 分钟/张（只调液化与点补），**一天 20 张 ≈ 40–80 分钟人工**。

## 3. 关键实现要点

### 3.1 套系锚点（解决「这套照片颜色不统一」）

- 每帧测出皮肤中位色（Lab）、曝光分位、白平衡增益；锚点取所有有效帧的**中位数**（坏帧不会拖歪整批）。
- 每帧修正 = **线性光**下的目标/当前比值，再拆成两部分：亮度 → 曝光补偿（上限 ±0.75 EV）、剩余每通道 → 白平衡微调（上限 ±12%）。
- 有锚点时，影调阶段自动关闭自身的白平衡/曝光归一（`applyWhiteBalance: anchor == nil`、`skipExposure: anchor != nil`），避免二次纠正。
- 实测：同一套 5 帧（曝光差 0.148 EV、蓝偏 ±7%）修正后 **肤色最大差 0.517 ΔE00、曝光差 0.0025 EV**（修正前是 14.37 ΔE）。

### 3.2 液化（影楼最常用、也最容易出事故的工具）

- 全部是**参数化**滑杆，不是自由画笔：每根滑杆对应一个带 smoothstep 衰减的局部挤压/放大，位移上限 = 滑杆值 × 比例，且被 `maxDisplacement` 硬封顶。
- 画框外圈位移**严格为 0**，背景不会被拉出画面；四条边都有锁定带。
- 8 个滑杆的合成量再做一次总上限（面部总强度 ≤0.6），防止「一次拉成蛇精脸」。
- 实测（1200 px 参考图）：轻度 1.8 px、全开 4.9 px、极限 8.2 px，相邻像素位移差 ≤0.196 px（无撕裂），边缘带 0.0 px。
- Swift 端 `RetouchReshape` 用自己的系数做了同一组不变量的 numpy 镜像验证（14 组滑杆组合）：`max|D| = 10.9 px`（上限 96 px 内）、4 邻域最大跳变 `0.1296 px`（门限 0.25）、外圈 8% 位移 **精确为 0**、左右镜像反对称误差 1.8e-15。两套系数手感不同，不变量一致，首次真机调一轮即可对齐。

### 3.3 换底与证件照

- 分割：Vision 人物分割（`.accurate`）→ iOS 17 前景实例分割兜底 → 再失败就保留原背景（绝不硬抠）。
- 发丝：羽化半径由脸宽推出（1.5–2.5 px），再补一次 edge-aware 反差恢复；过渡带用「新背景颜色 + 反 alpha」做去污，消除旧底白边。
- 证件照：按规格头高比（一寸 0.66、护照 0.72、美签 0.69）+ 眼睛落在 0.44 高度线，输出 300 dpi 精确像素（一寸 295×413、二寸 413×579、护照 390×567、美签 602×602）。
- 六寸相纸排版：一寸 5×2=10 张、美签 2×1=2 张，2 mm 间隙 + 四角裁剪标记。

### 3.4 交付包

- 命名 `前缀_yyyyMMdd_序号4.扩展名`；网页版按长边缩放（默认 2048）不放大，全尺寸走原图；色彩空间 sRGB / Display P3 由 CIContext 指定。
- 自研 ZIP（stored，UTF-8 文件名，CRC32 表驱动），失败自动清理半成品；超过 4 GB 明确报错而不是写出坏包。
- manifest 里带源文件名、交付文件名、尺寸、字节数、CRC32，冲印厂和客户都能对账。
- 选片页是单文件 HTML（内联 CSS/JS，无外链），客户勾选后一键复制结果发回。

## 7. 已知边界（照实说）

1. **这一版仍没有编译器验证**：Windows 上没有 swiftc。已做的替代验证是静态结构检查 + 语法解析 + 参考实现数值验证；类型/API 级问题需要在 Mac 上第一次 build 时暴露，风险点集中在 ImageIO 的 TIFF 属性、Display P3 profile、Vision 分割在真机的行为。
2. **液化强度手感**：Swift 端的参数化变形与参考实现是同一套不变量（位移上限、C1 平滑、边缘锁定），但系数是各自标定的，首次真机需要拿真实客片调一轮手感系数。
3. **瑕疵检测**仍是经典 LoG，不抹雀斑/痣；这是刻意的产品取舍，`blemishSensitivity` 可调。
4. **换底依赖 Vision 分割**：大逆光/透明纱/飞舞发丝会有边缘瑕疵，必须人审；这也是影楼常态（专业软件同样要人修边缘）。
5. **20 张/天不是吞吐上限**：瓶颈是人审；机器串行处理是为了内存平稳，不是性能限制。
6. **退款/返工接口**：版本库目前按批次建目录、照片靠 `resultURL` 映射，崩溃后能恢复批次但做不到「按张回滚」；要做到按张回滚需要给 `saveJPEG` 加 photo 标识（下一版）。
