# V25 · 拍摄端四件体验细节 + 截图自动识别

这轮补的是「用起来别扭」的地方：变焦硬切、音量键不能拍、拍的时候手机一转方向就乱、
大字号下取景框被挤。另外把 V24 遗留的「人工判断截图」自动化了。

---

## ① 布局魔数 288 → 实测高度

`CaptureView` 里原来用常量 `288` 预留底部（导演条 + 控制区）。超大字号（AX3+）控制区会长过 288，
取景框被挤小。

改法：
- 控制区/导演条用 `.background(GeometryReader { Color.clear.preference(key: BottomReserveKey.self, value: size.height) })` 量真实高度；
- `.onPreferenceChange` 里 `reserve = height + 16`，**差值 >1 才写回**（防止布局抖动反复触发）；
- `resolvedBottomReserve` 做兜底：非有限值或 ≤80 就回退常量 288；
- `previewBox` 用实测值算可用高度。

> 没用 `.onGeometryChange(for:)` —— 那是 iOS 18 API，部署目标 17.6 用不了。

## ② 变焦 ramp：不再「啪」一下

`applyDeviceZoom` 原来直接 `device.videoZoomFactor = factor`。

改法：
```swift
let rate = Float(max(4, min(18, abs(target - device.videoZoomFactor) * 10)))
device.cancelVideoZoomRamp()
device.ramp(toVideoZoomFactor: target, withRate: rate)
```
- 落点手感：Δfactor 0.1→rate 4；0.5→5；1.4→14；≥1.8→18（封顶）。1×→2× 约 0.07–0.15s，0.5×→5× 约 0.2–0.3s；
- `setZoom(_:animated:)` 默认 `true`，**所有旧调用点（滑杆/胶囊/导演自动变焦/捏合）一个字不用改**；
- 三处仍然直设（`animated: false`）：首次 installCamera 定位、拍照后的挂起补偿、设备未运行时的降级；
- **换设备**（超广角 ⇄ 主摄）不走 ramp —— 新设备没有「上一帧」，硬切才是对的；
- `controlsSettled` 已经含 `!device.isRampingVideoZoom`，ramp 期间自动快门门禁自然等着，不需要新状态。

## ③ 硬件快门（音量键 / 相机控制键）

按 Apple 文档，`AVCaptureEventInteraction` 在 **AVKit**（不是 AVFoundation）：
[Apple Developer · AVCaptureEventInteraction](https://developer.apple.com/documentation/avkit/avcaptureeventinteraction)。

```swift
import AVKit   // 物理快门在 AVKit 里
...
if #available(iOS 17.2, *) {
    let interaction = AVCaptureEventInteraction { [weak service] event in
        guard event.phase == .began else { return }   // 只在按下时触发，避免 .ended 再来一发
        service?.capture()
    }
    view.addInteraction(interaction)
    view.hardwareShutter = interaction                 // 记住实例，防重复挂载
}
```
- 和界面快门走同一个 `capture()`，`captureInFlight` 已经拦重复请求，不额外做防抖；
- 只在 `makeUIView` 里挂一次（SwiftUI 每次 update 不重复 addInteraction）。

**同时把校验闸门升级**（`scripts/verify.py`）：这条 API 之前是「一票否决」（首编安全），现在改成
**带保护才放行** —— 必须 `import AVKit`、必须 `#available(iOS 17.2)`、且只允许出现在
`Core/Camera/CameraService.swift`（其它文件出现即 FAIL）。

## ④ 旋转竞态：拍的时候别转

原来 `configureConnections()` 收到角度变化立刻改 connection，按快门的瞬间可能拍到「半横半竖」。

改法：
- `capture()` 里先刷一次最新方向，再 `rotationLockedUntil = now + 1.2s` 冻结；1.3s 后补刷一次
  （把锁期间被挡下的角度变化与换设备重建落定）；
- `configureConnections()` 顶部 `guard now > rotationLockedUntil else { return }` —— 窗口内
  **既不改 connection 角度，也不 publish `previewRotationAngle`**，整帧一致、预览一起冻住；
- `RotationCoordinator` 从 `previewLayer: nil` 改成拿到**真实 previewLayer**（`attachPreviewLayer`，
  weak 持有，`removeCurrentInput` 重建时复用同一层），前置镜像角度才准。

## ⑤ 截图自动识别（`ScreenshotDetector.swift`，219 行）

V24 那张五菱截图是我人工判的。现在自动判：三条启发式，550 长边代理，<15 ms，纯本地：

| 特征 | 阈值 | 真截图实测 | 实拍最高 |
|---|---|---|---|
| 边框带（四边各 6%）近纯黑/近纯白占比 | > **0.55** | 0.661 | 0.024 |
| 恒定行 / 恒定列占比（luma 行/列标准差 <0.008） | > **0.25** | 行 0.324 | 0.000 |
| 每通道 5 bit 量化后的唯一色数 | < 3000 | 1840 | 615（猫）/1814（窗景）/2504（红烧肉） |

判定：`isScreenshot = 边框 && (恒定行列 || 色数)`，置信度按命中条数 3/2/1 → 1.00/0.75/0.45。

**为什么必须有「边框」这条硬门槛**：色数单独完全不可靠 —— 缅因猫那张大片平滑地面只有 615 色，
旅行窗景 1814、红烧肉 2504，全都低于 3000。只有边框特征能把「截图」和「实拍」分开。

**我做的校准**（`tools/retouch_lab/screenshot_probe.py`，可复跑）：

```
wuling_mini_auto.jpg   border 0.661  rowC 0.324  colors 1840  → SCREENSHOT
其余 6 张              border ≤0.024                     → photo
```

**误判盲区与豁免**：白底商品图 / 建筑白墙 / 文档本身就是「平涂 + 白边」，统计上和截图同构
（白底商品图三票全中）。所以对 `商品摄影 / 建筑与室内 / 文档与翻拍 / 静物与艺术` 这四类
**豁免截图改写**（它们本来就走 product/document 口径，白底是正常形态，按截图处理会把最需要锐化的
商品图 Look 关掉、锐化封到 0.12）。真正的截图丢进人像/旅行预设仍会被接管为 document 口径。

命中后效果：
- `parameters.applyLook = false`（不套风格 LUT、跳过 Lightroom 核心阶段）、`clarityAmount = 0`、
  `sharpenAmount ≤ 0.12`；
- 门禁口径强制 `.document`（纹理 0.60–1.50、SSIM ≥0.92、不判肤色），优先级压过 category；
- 质检报告 notes 首条写清依据：
  `提示：检测为截图/界面图（置信度 1.00），已切文档口径并跳过风格调色。依据：边框纯黑/纯白占比 66.1%（阈值 55%）；恒定行 32.4% / 恒定列 0.0%（阈值 25%）；量化色数 1840（阈值 3000）`

## 真机待验（本机只有静态检查，逐条列出）

1. **AVCaptureEventInteraction 归属**：已按 Apple 文档确认在 AVKit；若首次 `swiftc -typecheck` 报找不到类型，把 `import AVKit` 改成 AVFoundation。
2. 音量上/下键与 iPhone 16 相机控制键是否都触发 `.began`；按住不放是否只出一张。
3. 拍完立刻转 90°，成片方向是否与按下快门那一刻一致；1.3s 后预览是否自动跟上。
4. `attachPreviewLayer` 之后首屏角度是否抖一次（coordinator 先 nil 建、attach 后重建）；前置镜像时画面是否不歪。
5. ramp 手感：0.5×→5× 拖滑杆是否平滑；拿不到 device lock 的降级路径要看 log。
6. AX3–AX5 下取景框是否随实测控制区高度自动让位；**AX5 + iPhone SE** 这种「控制区比屏幕还高」的极端组合可能仍需把控制区改成可滚动（当前取景框有 140pt 下限）。
