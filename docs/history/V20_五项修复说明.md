# V20 修复说明（build 28 · 1.2）

本版只做一件事：把你提的五条问题逐条改到位。V19 的代码结构、已有功能（图库、学院、设置、交付清单、版本历史、后台批处理）全部保留，没有降级。

---

## 1. 快门挡住变焦和滤镜（最严重的一条）

**V19 根因**：`CaptureView.body` 里挂了**两个** `GeometryReader`。第二个专门把 `fixedPortraitShutterDock` 浮在最上层（`.padding(.bottom, 86)`），它不属于布局流，纯靠 ZStack 叠上去；`portraitLayout` 只能用 `.padding(.bottom, 120)` 硬顶，实际控制区高度（滤镜条 + 变焦滑杆 + 倍率输入 + 意图行 + 主体行 + 效果前预览）远超 120，于是「1.00×」「环境/安静」「滤镜行」全被那条黑色胶囊压住。

**V20 改法**：
- 删掉第二个 `GeometryReader`、`fixedPortraitShutterDock`、`controls(compact:)`、`.padding(.bottom, 120)`。
- 快门条改成 `.safeAreaInset(edge: .bottom, spacing: 0) { shutterBar }`：由系统在安全区里让位，**内容区物理上不可能被它盖住**，竖屏横屏共用同一条。
- 竖屏固定五段：顶栏(52) → 取景框（`CaptureLayout.fit` 在剩余高度里求最大尺寸）→ 导演信息条 → 控制区（滤镜条 / 变焦快捷胶囊 / 意图 / 主体 / 效果前预览）。
- 连续变焦滑杆、倍率输入框从「展开挤压布局」搬进 `.sheet` 弹层（`.presentationDetents([.height(260)])`），点当前倍率胶囊才弹，**滑杆永远不会压住滤镜**。
- 取景框内那块黑色「请稳住手机」胶囊删除，导演提示移到取景框**外面**的独立信息条。

## 2. 横向没做，只能竖着拍

**V19 状态**：`landscapeLayout` 写了，但只有系统自动旋转成功才会走到；用户机上转不过去（方向锁、或 `requestGeometryUpdate` 未生效），且横屏没有快门。

**V20 改法**：
- 保留自动旋转（`allowsRotation → .allButUpsideDown`）。
- 新增顶栏「横竖屏切换」按钮 → `OrientationPolicy.toggleLandscape()`：改 mask → 对**所有** window 根控制器 `setNeedsUpdateOfSupportedInterfaceOrientations()` → `requestGeometryUpdate(.iOS(interfaceOrientations:))` → 完成回调再刷一次。设备不转也能强制横过来。
- `OrientationPolicy.isLandscapeNow` 用 `scene.effectiveGeometry.interfaceOrientation` 判断，不看设备方向。
- 横屏布局重写：左边取景框（`4:3`/实际帧比自适应），右边 250pt 独立滚动控制栏，快门条仍由 `safeAreaInset` 常驻底部 —— 横屏也有快门。

## 3. 拍照还是镜像

**V20 改法**：
- 新增 `@AppStorage("mirrorFrontCamera")`，**默认 false（不镜像）**，老用户升级后也是不镜像。
- 顶栏新增「前置镜像」开关（仅 `camera.cameraPosition == .front` 时出现，后置永远不镜像）。
- 预览层：`CameraPreview.mirrored` + `camera.cameraPosition` 双条件决定 `isVideoMirrored`；镜像时角度改用 `videoRotationAngleForHorizonLevelPreview`（前置镜像画面的正确角度），并同步翻转实时效果层，点选主体的坐标也做了反向映射。
- 成片：`CameraService.didFinishProcessingPhoto` 只在「前置 + 开关开」时做方向归正后水平翻转并重编码；失败回退原始 JPEG（宁可不解镜像也不丢照片）。深度遮罩同向翻转，不会和主图错位。
- 结果：默认预览与成片一致、都不镜像；想要自拍镜面效果时开关一开，预览和成片**一起**翻。

## 4. AI 导演是个屁，只会说「等待可靠画面」「请稳住手机」

**V19 根因**：`DirectorDecision.summary` 取不到「机位」就退到「导演策划」再退到「等待可靠画面」；变焦目标每帧重算导致抖动；没识别到主体时只给一句「不根据猜测自动追焦放大」，没有任何可执行动作。

**V20 改法**（只动 `DirectorEngine.swift`）：
- `summary` 优先级改为 机位 → 构图 → 时机 → 导演策划，最后兜底也是可执行句，**永远带方向 + 幅度**：
  - 「主体偏左 0.15，机位向右移动半步」
  - 「主体偏上 0.08，略微下压机位」
  - 「已自动推近至 1.62×，再靠近 45cm 更满」
  - 「构图已就位（居中），稳住 1 秒即自动拍摄」
  - 「未锁定主体：把人物放到画面中央三分之一，点击屏幕锁定」
  - 「无主体场景：地平线对齐，天空留 1/3，最亮处放在三分线交叉点」
- 每次评估都补齐 **构图 / 机位 / 曝光 / 时机** 四域 evidence，另按需加 水平 / 光线色彩 / 滤镜 / 景物定位 / 拍摄技巧 / 景深，每条 action 都带数字。
- 变焦四道闸：**上限**（人物占高 ≥12% 时封顶 min(native×2, 3.0) 且 ≤2×；只有运动/特写且占比 <8% 才准吃满硬件上限）→ **死区 8%** → **最短 1.2s**（按真正下发计时，被门控告吹掉的建议不吃间隔）→ **一阶低通 0.35**。彻底消除来回抽动。
- `ready` 公式逐字未改，自动快门门禁没有放宽，`blockers` ≤3 条且条条具体。

## 5. 精修 / AI 双引擎 + 精修后没有 AI 修图建议

**V19 状态**：`engine` 只是个 Picker，AI 面板要被付费开关和解锁顺序卡住，切过去找不到回来的路；本地精修完成后只给一个「质量门禁未通过」，**不告诉你 AI 阶段该怎么修**。

**V20 改法**（`CommercialRetouchView.swift`）：
- 页面最顶端常驻三页签：**本地精修 / AI 修图 / 双引擎**，三个面板都在同一页、状态互不丢；本地面板底部有「→ 去 AI 修图」，AI 面板顶部有「← 回本地精修」，双引擎面板是「① 先执行本地精修」「② 带着建议执行 AI」。
- 本地精修完成后**立即产出「AI 修图建议」卡片**：逐条 `指标 → 现象 → 建议动作 → 建议参数`，全部带数字，例如
  - 肤色 ΔE00 4.09 超 3.00 → 「只做肤色自然化、拉回 ≤2.00、禁换色禁暖滤镜 / 强度 ≤0.85 / 预设 商业自然」
  - 全图高光裁切 0.0157 超 0.0100 → 「恢复高光暗部层次，禁纯白纯黑 / 保留 1%–99% 动态范围」
  - 纹理保留 <0.50 → 「回补皮肤纹理毛孔，禁止再磨 / 强度 ≤0.80」
- 同卡片里给出一段**可直接发送的 Seedream 提示词**（可编辑），三个按钮：「带着建议去 AI 修图」（把建议、预设、强度一起带进 AI 页）、「按建议重跑本地精修」、「复制提示词」。
- 提示词发送前自动拼上身份保持约束，超 900 字符截断。
- QC 指标里原来露出来的 `skin_pixel_de_p95_info` 已加中文标签「肤色ΔE P95（信息）」，不再显示原始键名。

## 6. 精修有些还通过不了（第 5 条的根因）

**V19 根因**（`RetouchPipeline.process`）：
1. `RetouchParameters.maxPasses` 默认 **2**，重试没几次机会；
2. 重试分支只处理 纹理 / 裁切 / 接缝，**肤色 ΔE 和肤色明度偏移掉进最后的 `else { break }`**，所以「肤色ΔE00 4.09」永远修不动；
3. 跑满轮数后直接把不合格图交出去。

**V20 改法**：
- 轮数下限抬到 `max(3, maxPasses)`；重试分支补全 肤色ΔE / 明度偏移 / SSIM 三条退让。
- 新增兜底合规 pass `RetouchCompliance`：
  - **肩/趾压缩**（CIColorKernel 一次全图）：`x≤0.08 → 0.014+0.066·(x/0.08)`，中段斜率 0.9976（中间调几乎恒等），`x≥0.92 → 0.918+0.064·((x-0.92)/0.08)`。任何通道落在 `0.014…0.982`，luma 是通道凸组合 ⇒ `clipping_full`、`clipping_skin` 归零，且不动中间调（纹理/SSIM 基本不受影响）。
  - **肤色拉回**：1100 代理上量皮肤区 Lab 中位数 ΔE00，>2.0 就用 `CIColorMatrix` 通道增益 + `CIBlendWithMask` 只作用在皮肤遮罩内，阻尼 0.85、最多 2 次迭代。
  - 压缩**按需**触发：已合规一个像素都不动；另有 8 位 LUT 兜底（不依赖工作色彩空间），两次取裁切更小者交付。
- 仍不过时**不抛错、不换图**，只在 notes 末尾追加唯一可执行动作（如「→ 建议把精修强度降到 0.85 以下，或改选商业自然预设」），`passed` 保持门禁真实结论。

## 真机回归清单（建议按这个顺序点一遍）

1. 拍摄页竖屏：滤镜行、变焦胶囊、意图行、「效果前预览」全部可见可点，快门条在黑底上、不压任何控件；点当前倍率弹出变焦面板。
2. 点顶栏横竖屏按钮 → 应立刻横过来；横屏下快门条仍在底部，右栏可上下滚动；再点一次回竖屏。
3. 切前置：顶栏出现「前置镜像」，默认关闭；拍一张，相册里那张应与取景框方向一致、**不镜像**；打开开关后再拍，预览与成片**同时**变成镜面。
4. 对准人物：导演信息条应出现带数字的指令（如「主体偏左 0.15，机位向右移动半步」），不再出现「等待可靠画面」；连续移动时变焦不应反复抽动。
5. 精修 → 导入一张人像 → 执行本地精修：应出现「AI 修图建议（N 条）」卡片与提示词；肤色 ΔE、全图裁切两项应落在阈值内（ΔE ≤3.00、裁切 ≤0.0100）。
6. 点「带着建议去 AI 修图」→ 自动跳到 AI 页签并填好提示词与强度；点「← 回本地精修」能直接回来，结果不丢。

## 已知限制（说清楚，不糊）

- 本机没有 `swiftc`，全部改动只做了 tree-sitter 语法检查（`files=58 syntax_failures=0`）+ 工程自检 `verify.py RESULT: 0 failures` **类型级编译必须在 Xcode 里跑一次**；如有个别类型错误，多半集中在 SwiftUI 修饰符链（`UnevenRoundedRectangle` / `.monospacedDigit()` / `presentationDetents`），都是 iOS 17.6 可用 API。
- 竖屏底部预留高度是常量 288pt，用于保证取景框不挤压控制区；超大辅助字号（AX3+）下取景框会被压小（但**不会**再出现遮挡），建议用最大字号回归一次。
- 手动强制横屏后 mask 会收窄成单方向，回竖屏时异步恢复；系统开启竖排锁定时的行为以真机为准（已加 completion 二次刷新兜底）。
- 镜像成片会在拍照回调线程多做一次全分辨率翻转（约 50–120 ms），失败自动回退原始 JPEG。
- 极端暗图（大片死黑占 60% 以上）抬高黑位 4/255 会压 SSIM；已做成按需触发，仍超限时由 notes 提示降强度，不会悄悄交出坏图。
- studio 批处理那条 `process(_:preset:adjustments:anchor:)` 路径**刻意没接**兜底合规（它的 QC 是在液化/换底/证件照裁切**之前**打的，接进去会把剪影误判成结构失败）。单张精修路径已全部接入。
